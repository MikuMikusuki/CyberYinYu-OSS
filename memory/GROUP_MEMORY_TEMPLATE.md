# 群记忆样板

每个群使用独立文件：`memory/groups/<group_id>.json`。例如群 `100000001` 使用 `memory/groups/100000001.json`。机器人只在该群对话时读取对应文件；其他群和私聊不会拿到这份内容。新群首次触发回复时会自动创建空档案。

样板档案故意留空，避免把未核实的聊天内容写成事实。群消息即使没有 @ 机器人，也会在出现“记忆/记住/别忘了”、长度达到 32 字，或带有群级背景提示词时，让 DeepSeek 判断是否需要 add/update/delete；普通短消息不会触发这次额外判断。只有高置信的群级背景才会自动写入。每个群最多 20 条，每条最多 300 字；重复内容、敏感字段和非白名单分类会被拒绝。机器人也会把该群的记忆候选项提供给回复模型，由它按当前话题判断哪些相关。私聊不读写群记忆。

任何群成员在群里发“记住：……”时，都会把冒号后的内容直接写进该群的 `shared_context`，不再依赖 DeepSeek 自行猜测。记忆按群号存储并对该群所有成员共享；敏感内容、重复内容和超过容量的内容仍会被拒绝。机器人会明确回复是否成功写入。

## 人称主体一律锚到 QQ 号

群名片会改、会重名，所以记忆里凡是“谁是谁”，主体都写成 `QQ12345678（当时的群名片）`，例如：

```
QQ1000000002（老王）是王工
QQ1000000003（阿伟）是老张
```

- QQ 号是稳定身份；括号里的群名片只是记录当时的显示名，改名不影响指代。渲染进提示词时也会告诉模型“以 QQ 号为准”。
- 裸的 `他是X`、`我是X` **不写入**：离开当轮就再也对不上人。发“记住：他是 XXX”时请 @ 他本人或带上 QQ 号，机器人会把主语换成 QQ 号；判断不出“他”是谁时会直接反问一句，而不是硬猜。
- `我是X` 取发言者自己的 QQ；`他是X` 优先取被引用消息的发言者，其次取本条消息里唯一被 @ 的人。
- 自动归纳（DeepSeek 判断路径）同样按这个规则写；证据里每行的 `名字（QQ号 xxx）` 就是该发言者的身份。
- 纯别名条目（`甲是乙`）保持原样，仍然参与“称呼链”推导；只是不再允许出现没有 QQ 的人称代词主体。

存量里如果有 `他是X` 这类老条目，用 `dataset/fix_memory_subjects.py` 体检（默认 dry-run）：`我` 开头且 `source` 带 QQ 的能自动修，`他` 开头的不猜，只列出来让本人重说一次。

仍可手工检查和修改 JSON。条目格式例如：

```json
{
  "category": "recurring_topics",
  "content": "群里常聊桌面硬件和电子 DIY。",
  "confidence": "medium",
  "source": "人工确认",
  "updated_at": "2026-09-28"
}
```

可用分类：

- `group_context`：群的整体背景。
- `shared_context`：群成员共同知道的背景。
- `recurring_topics`：经常讨论的话题。
- `inside_jokes`：群内梗和特定说法。
- `group_preferences`：群里明确表达过的偏好。
- `ongoing_threads`：还在持续讨论的事情。

机器人只把 `category` 和 `content` 放进当前群的提示词。自动整理的条目还包含 `id`、`confidence`、`source` 和 `updated_at`。每次请求都会重新读取文件，因此编辑保存后下次群聊就会生效，无需重启机器人。

建议只保存简短、可复核、对群内交流确实有用的共同背景；不要复制原始聊天记录、密钥、联系方式、住址、医疗/财务信息或未经确认的传闻。被筛选的近期群聊片段和群记忆会发送给 DeepSeek API 做回复及判断，因此不要写入不希望发送到 API 的内容。

现有短期上下文仍按群号区分、保存在内存中，并受 `CONTEXT_MAX_TURNS` 和 `CONTEXT_TTL_SECONDS` 控制。
