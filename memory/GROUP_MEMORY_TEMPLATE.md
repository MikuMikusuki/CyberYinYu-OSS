# 群记忆样板

每个群使用独立文件：`memory/groups/<group_id>.json`。例如群 `123456789` 使用 `memory/groups/123456789.json`。机器人只在该群对话时读取对应文件；其他群和私聊不会拿到这份内容。新群首次读取时会自动创建空档案。

## 写入方式

- **自动归纳**：群消息出现「记忆 / 记住 / 别忘了」、长度达到 32 字，或带有群级背景提示词时，后台会让模型判断是否需要 `add / update / delete`；只有高置信的群级背景才会写入。
- **显式请求**：成员说「记住：……」时，后台审核器分三档：`save` 自动写入并总结；`confirm` 挂起等 owner 确认；`reject` 直接回绝。审核不阻塞消息流。
- **owner 确认**：`OWNER_QQ` 本人在群里回「确认」或「拒绝」（短消息，默认 30 分钟内有效）。
- **手动删除**：owner 发 `#删除记忆 <序号|id 前缀|内容片段>`。

每个群最多 **200 条**，每条最多 **300 字**；重复内容、敏感字段和非白名单分类会被拒绝。私聊不读写群记忆。

仍可手工检查和修改 JSON。条目格式例如：

```json
{
  "category": "recurring_topics",
  "content": "群里常聊桌面硬件和电子 DIY。",
  "confidence": "high",
  "source": "人工确认",
  "updated_at": "2026-10-21"
}
```

可用分类：

- `group_context`：群的整体背景。
- `shared_context`：群成员共同知道的背景。
- `recurring_topics`：经常讨论的话题。
- `inside_jokes`：群内梗和特定说法。
- `group_preferences`：群里明确表达过的偏好。
- `ongoing_threads`：还在持续讨论的事情。

机器人只把 `category` 和 `content` 放进当前群的提示词。自动整理的条目还包含 `id`、`confidence`、`source` 和 `updated_at`。每次请求都会重新读取文件，因此编辑保存后下次群聊就会生效，无需重启机器人。

建议只保存简短、可复核、对群内交流确实有用的共同背景；不要复制原始聊天记录、密钥、联系方式、住址、医疗/财务信息或未经确认的传闻。被筛选的近期群聊片段和群记忆会发送给模型 API 做回复及判断，因此不要写入不希望发送到 API 的内容。

短期上下文按会话区分、保存在内存中，并受 `CONTEXT_MAX_TURNS` 和 `CONTEXT_TTL_SECONDS` 控制。
